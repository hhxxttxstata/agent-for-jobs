# JD 解析与匹配（jd-analysis）

解决痛点 P1「JD 信息过载」：把几百到上千字的 JD 压缩成一张**可比较、可决策**的卡片。

## 工作流

1. **取输入**：JD 原文在用户消息里，或在给出的文件路径中（用 read 读取）。
2. **读画像**：用 read 读取 `data/profile/master-resume.md`；若文件不存在，提示用户先初始化主简历，中止流程。
3. **生成卡片**：严格按【输出模板】填充。逐字段判断：JD 明确写了才填；没写的填 `未提及`。宣传性语句（"广阔的成长空间""扁平化管理"）不进卡片，除非它是福利/流程的关键信息。
4. **匹配打分**：对照主简历，按【评分标准】给四个分项打分并加权求和，得出 0—100 的匹配度。
5. **落盘**：用 write 写入 `data/jds/<公司>-<岗位>.md`（文件名去空格与非法字符；若目标文件已存在则覆盖，并保留原文件中的 `状态` 字段值）。
6. **回复**：给用户卡片摘要（基本信息 + 硬性要求 + 匹配度 + 一句话投递建议），并注明卡片落盘路径。

## 评分标准

- **技能匹配（40）**：JD 硬性技能在主简历中直接出现的比例与深度。
- **经历匹配（30）**：项目/实习/竞赛经历与 JD 业务场景的相关度。
- **学历门槛（15）**：完全达标 15；"硕士优先"且用户为硕士 15、本科 8；硬性不符 0。
- **方向意向（15）**：与 `data/profile/master-resume.md` 求职意向的重合度。

打分要克制：80+ 意味着"几乎为这个岗位量身定做"；60-79 值得认真准备投递；40-59 顺手投；40 以下建议不投。


- **投递建议分层（硬性要求）**：每张卡片的「投递建议」必须以优先级标签开头，按总分映射：80+ → `高优先`；60-79 → `中优先`；40-59，或存在 1-2 周内可补齐的关键差距 → `暂缓`；40 以下或命中红线 → `不投`。标签后接 1-2 句理由，理由必须引用总分；卡片「薪资范围」不是"未提及"时，用半句话点明薪资对优先级的影响（仅基于卡片内信息）；竞争激烈程度只在 JD 原文有线索（如"急招""批量招聘""名额有限"）时提及，没有线索就注明"竞争情况信息不足"，禁止编造。禁止只写"建议投递"这类无分层的笼统结论。
## 示例边界

- JD 信息极少（如群里转发的一句话招聘）：能填的填，其余写"未提及"，匹配度照常给出但在投递建议中注明信息不足的风险。
- JD 与技术无关（实习/行政等杂岗）：照常解析，匹配度按标准打，投递建议如实说不匹配。
- 用户粘贴了多个 JD：逐个解析，每个单独落盘一张卡片。


- 极简 JD 中出现的招聘方组织名（如"光子工作室群""XX 实验室""XX 事业部"）就是 frontmatter `公司` 字段的合法取值：按原文措辞原样填入；不要因为它是工作室群/实验室/事业部而非正式注册公司名，就改写成母公司名或填 `未提及`。前述"能填的填"中的"能填"包含此类组织名。
