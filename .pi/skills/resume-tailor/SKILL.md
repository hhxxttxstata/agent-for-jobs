# 简历定制（resume-tailor）

解决痛点 P2「多版本简历来回改」：从唯一事实来源 `data/profile/master-resume.md` 派生定制版，每一处修改**可追溯**，版本集中管理。

## 工作流

1. **定位 JD**：用户给出公司/岗位名或文件名 → 在 `data/jds/` 找到对应卡片（用 ls + read）；找不到时提示先跑 jd-analysis，中止。
2. **读主简历**：read `data/profile/master-resume.md`。
3. **读风格规范**：read `data/profile/resume-style-guide.md`——项目条目解剖（`### 项目名（时间）` + 核心技术行 + `**加粗标签**：方案+量化结果` 要点）、语言规范（量化加粗、拒绝空话）是产出格式的硬性要求。
4. **定制**：只做三件事——
   - **重排**：把与该 JD 最相关的项目/技能模块前移；
   - **改写**：项目描述措辞向 JD 关键词靠拢（用 JD 的词汇重述已有事实，不改变事实本身），按风格规范的条目解剖组织每条要点；
   - **侧重**：调整量化指标的呈现顺序与强调程度（数字加粗），补强"JD 关心什么就先讲什么"。
5. **生成 changelog**：逐项记录修改（见模板 `## 定制说明` 表格）。
6. **落盘**：write 到 `data/resumes/<公司>-<岗位>.md`（已存在则覆盖）；然后读取 `data/resumes/index.md`，用 edit 把新版本行插入索引表（已存在同名行则更新日期）。
7. **生成投递版 PDF**：bash 运行 `node .pi/skills/resume-pdf/scripts/md2pdf.mjs "data/resumes/<公司>-<岗位>.md"`（详见 resume-pdf 技能），得到同名 `.pdf`；用户明确只要 markdown 时可跳过本步。
8. **回复**：定制简历摘要 + 主要修改点（3 条以内）+ md 与 PDF 落盘路径，并提醒：投递前用 `read` 通读一遍定制版确认。

## 输出模板（小节标题一字不差）

```markdown
---
公司: <公司名>
岗位: <岗位名>
源JD: data/jds/<公司>-<岗位>.md
基线: data/profile/master-resume.md
生成日期: <YYYY-MM-DD>
---

# <姓名> - <岗位名> 定制简历

<按主简历的结构输出完整简历（个人信息/教育背景/项目经历/技能清单等），
模块顺序与内容按本 JD 定制，项目要点严格按 resume-style-guide.md 的条目解剖输出：
`### 项目名（时间）` + `核心技术：…` + `**加粗标签**：方案+量化结果`（数字加粗）。
个人信息与教育背景一字不改。>

## 定制说明

| 位置 | 原文（摘要） | 修改后 | 理由 |
|---|---|---|---|
| <模块/条目> | <主简历中的原句摘要> | <定制版的新句> | <对应 JD 的哪条要求/关键词> |
```

## 红线（违反任何一条即任务失败）

1. **不虚构**：不新增主简历中不存在的经历、项目、数据、技能、证书。
2. **不删除**教育背景；个人信息（姓名/电话/邮箱）原样保留。
3. 每处实质修改必须出现在 changelog 表格中；改写前后语义必须等价（措辞可以变，事实不能变）。
4. 关键词匹配只针对主简历已有的能力——JD 要求但用户不具备的，**不写进简历**（差距记录在 JD 卡片的"差距与应对"里）。
